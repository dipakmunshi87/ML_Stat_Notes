Libraries

What to install

Start here

DeepXDE — the standard research library. ODEs, PDEs, integro-differential and inverse problems; backends for TensorFlow, PyTorch, JAX and PaddlePaddle; DeepONet built in. Documentation at deepxde.readthedocs.io. If you are trying PINNs for the first time, use this.

Lu, Meng, Mao & Karniadakis, SIAM Review 63, 208 (2021).

Production scale

NVIDIA PhysicsNeMo — formerly Modulus, now open source. Multi-GPU, industrial geometries, neural operators and PINNs together. Heavier to learn; the right choice if you need to scale beyond one device. Code at github.com/NVIDIA/physicsnemo.

Research in JAX

jaxpi — the reference implementation of the modern training tricks: NTK weighting, causal training, Fourier features, curriculum. From the group that published most of them. Read it even if you do not use it.

Wang, Sankaran & Perdikaris, arXiv:2308.08468.

Writing your own for a one-dimensional problem is about two hundred lines and teaches you more than any library. The engine behind these pages is roughly that size.

Libraries, continued

The rest of the field

Julia

NeuralPDE.jl — part of the SciML ecosystem, with symbolic PDE specification through ModelingToolkit and tight integration with Julia's differential-equation solvers. The best story for mixing learned and classical components.

Lighter alternatives

NeuroDiffEq for ODEs with hard constraints built in; SciANN as a thin Keras wrapper; PINA on PyTorch Lightning; TorchPhysics for geometry-heavy problems.

Operators and benchmarks

neuraloperator — the reference FNO implementation. PINNacle — a 20-problem benchmark suite, the fastest way to find out whether a method works outside its own paper.

Check the repositories before committing: this part of the field moves quickly and several once-prominent projects are now unmaintained.

The advice nobody gives

Before installing anything, spend an afternoon writing a PINN for a one-dimensional problem with a known exact solution, in whatever framework you already use. You will hit the scaling issue, the constraint issue and the weighting issue in that order, and every page of this set will make more sense afterwards.

Watch for

Libraries default to soft boundary conditions and unit loss weights, because those are general. Both defaults are the wrong choice for most problems, and neither will announce itself. Check what your library is doing before concluding that PINNs do not work on your equation.

Hardware

One- and two-dimensional problems train perfectly well on a laptop CPU — the demonstrations in this set run in a browser tab. GPUs matter above about 10410^4104 collocation points, which means three dimensions and up.

The "write your own first" advice is not purism. Library abstractions hide exactly the three things that determine whether your problem trains.

Getting started

Your first problem, in an afternoon

Designed to fail fast rather than slowly. Each step should take minutes; if one takes a day, that is the answer to whether this method suits your problem.

  1. Pick a problem with a known solution. Not the one you care about. Manufacture one: choose uuu, apply the operator, call the result fff.
  2. Non-dimensionalise. Every coefficient O(1)O(1)O(1), domain mapped to [−1,1][-1,1][−1,1].
  3. Impose the boundary conditions hard. Check the ansatz keeps the network's job O(1)O(1)O(1) across the whole domain.
  4. Train and measure the relative L2L^2L2 error against the exact solution — not the loss. If it is not below a few per cent, nothing later will help.
  5. Solve the same problem classically and compare cost and accuracy. Do this before you are emotionally invested.
  6. Only now move to the real problem, and only if step 5 did not settle the question.
What to report, always

Relative L2L^2L2 error against a reference; the residual plotted across the domain; each loss term separately; wall-clock time and step count; the result from at least three random seeds. A paper or talk without these is not reporting a measurement.

When to stop

If a classical solver handles your problem in seconds and you only want the solution, stop. The honest use cases are inverse problems, unobservable fields, high dimension, non-local operators, and equations with no good classical method. If yours is none of these, the answer is a solver.

Where this set goes next

The companion set on neural operators and numerical solvers covers the other approach: learning the map from data to solution once, so that new instances are a forward pass rather than a new training run — and how both compare against classical methods.

Step 5 is the one people skip, and it is the one that saves months.
