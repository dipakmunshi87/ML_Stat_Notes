The picture

Gravity, and attention

Each particle sums a contribution from every other one:

Fi=∑jGmjrij2⏟the kernel  r^ij.F_i=\sum_j \underbrace{\frac{Gm_j}{r_{ij}^2}}_{\text{the kernel}}\;\hat r_{ij}.Fi​=j∑​the kernelrij2​Gmj​​​​r^ij​.

Attention is the same sum, with two differences.

The two differences

1. The weights are normalised: each row sums to one, so you get an average, not a total.

2. The kernel is learned. Newton hands you Gm/r2Gm/r^2Gm/r2; here nobody hands you anything, and the network works out which pairs matter.

"Attention is gravity with the kernel left blank" is the single most useful sentence for a physics audience.

Written out

Three projections and one average

Stack your objects as rows of XXX, make three copies of each row, score every pair, average:

Attn(X)=softmax ⁣(QK ⁣⊤dk)V.\mathrm{Attn}(X)=\mathrm{softmax}\!\left(\frac{QK^{\!\top}}{\sqrt{d_k}}\right)V .Attn(X)=softmax(dk​​QK⊤​)V.

QQQ is what each object looks for, KKK what it advertises, VVV what it passes on. The pair score is qi ⁣⋅ ⁣kjq_i\!\cdot\!k_jqi​⋅kj​.

The physics reading

The softmax is a Boltzmann weight, Aij∝e qi⋅kj/dkA_{ij}\propto e^{\,q_i\cdot k_j/\sqrt{d_k}}Aij​∝eqi​⋅kj​/dk​​: scores are energies, the denominator is a partition function, and the size of q ⁣⋅ ⁣kq\!\cdot\!kq⋅k is an inverse temperature. Cold, one term dominates — a lookup. Hot, all contribute — an average. And that temperature is learned, not set by you.

Pointing at the Boltzmann weight is usually the moment a physics audience relaxes: it is a familiar object with an unfamiliar name.

A worked case

Five detectors, one question

Here is a problem small enough to follow by hand, and it is the one the demonstration solves.

Five detectors report a reading each. A sixth token asks a question: what did detector 3 read? The network must return that reading.

Attention solves this exactly. Let the query and key projections look only at the label part of each token, so that the score is large when the labels match and small when they do not:

qask ⁣⋅ ⁣kj=β δℓj, ℓask.q_{\rm ask}\!\cdot\!k_j=\beta\,\delta_{\ell_j,\,\ell_{\rm ask}} .qask​⋅kj​=βδℓj​,ℓask​​.

Then the softmax over jjj puts almost all the weight on the matching detector, and the value projection — which looks at the reading part — copies it out. For large β\betaβ the answer is exact.

Nobody tells the network any of this. It has to find those three projections by itself, starting from random numbers.

In one line

The query asks "who has label 3?", the keys answer, and the values carry the reading. A lookup table, built out of dot products.

The temperature again

β\betaβ here is the same inverse temperature as before. Training makes β\betaβ grow — the attention cools from a broad average onto a sharp lookup. You can watch that happen on the next slide: the bottom row of the matrix starts flat and collapses onto one square.

The delta-function construction is worth doing on a board: it shows attention can represent an exact lookup, which is not obvious from the equation.

What it found

Exactly the construction on slide 4 — match the labels, copy the reading — discovered from nothing but examples of the right answer. Two hundred steps is enough for the attention to be right almost every time; the remaining training is spent sharpening the copy.

Keep it in proportion

This is a toy. It shows the mechanism honestly, and it is not evidence about anything at scale. That distinction is the subject of page 7, and it applies to every number on this site.

The 5% starting accuracy is chance for six tokens, and worth pointing out.

Three sentences

Attention is an all-pairs sum with the kernel learned from data.
The softmax temperature is learned too — it decides between a lookup and an average.
Nothing in the operation refers to order, so it sees a set.
