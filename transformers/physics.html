Part 3 of 8 · the fit

Your data is a set,
not a grid

Particles in an event. Galaxies in a survey. Hits in a detector. Points in an unevenly sampled light curve. None of these has a natural order, and hardly any has a fixed size. Attention is the only common architecture that takes that seriously.

The picture

Which of these is your problem?

If the answer is the left-hand picture — a regular grid, with physics that is local — use a convolution. It is cheaper, and it builds in the locality you already know about.

If it is the right-hand picture, a convolution has nothing to grip. You would have to invent an order, pad to a fixed length, and let the network learn a symmetry you knew about all along.

This one slide answers the question most people actually have, which is whether to reach for a transformer at all.

Four properties

What the sum gives you for free

1 · Order does not matter

Shuffle the objects and the answers shuffle with them, exactly — not approximately, and not because the network learned it. Measured on the model trained further down this page: the worst change over fifty random shuffles is 4×10−16, which is rounding error.

2 · Any number of objects

The same weights work for 12 tracks or 300. No padding, no truncation, no separate model per size. Measured below: a model trained on sets of 5 works unchanged on sets of 12.

3 · Everything couples to everything

Every pair is connected in a single layer. A convolution needs depth ∼L/w\sim L/w∼L/w to connect points a distance LLL apart; attention needs one layer whatever the distance. For a correlation that does not fall off, that is the difference between a natural model and a strained one.

4 · The objects need not be alike

A token can be a track, a calorimeter cluster, a photometric point with its error bar, or a simulation parameter — all in the same set. Give each one its coordinate as a feature and uneven sampling stops being a problem, because there is no grid to be uneven against.

Property 4 usually decides the choice in practice: real datasets are heterogeneous, and most alternatives require them not to be.

Concretely

What a token is, in six cases

A collider event

One token per reconstructed object: (pT,η,ϕ,m,type)(p_T,\eta,\phi,m,\text{type})(pT​,η,ϕ,m,type). Unordered, and a different size every event. The attention between two tokens is, physically, how correlated those two objects are.

A galaxy catalogue

One token per galaxy: position, redshift, magnitude, shape. A field of 10410^4104 galaxies is a set of 10410^4104 tokens — at which point the all-pairs cost bites, and you restrict to neighbours.

A light curve

One token per observation: (t, f, σf, band)(t,\ f,\ \sigma_f,\ \text{band})(t, f, σf​, band). Gaps and uneven spacing need no special treatment because ttt is a feature, not a row number.

A simulation

Tokens as patches of a field, or mesh cells with their coordinates. Attention supplies the non-local part that a local stencil cannot — a learned version of the integral term in a kinetic equation.

Detector hits

Raw hits as tokens: position, time, charge. Tracking becomes the question of which hits belong together, which is exactly what an attention matrix says.

A mixture

Nothing stops the set holding different kinds of thing at once: measurements, instrument state, cosmological parameters, a label. That is the normal case, not a complication.

When the token choice feels forced, that is usually a sign the architecture is wrong for the problem.

What the matrix means

A picture of who influences whom

Take masses on a ring. If the springs only join neighbours, the coupling matrix is a band down the diagonal. If the force is long-range, it is broad. The matrix is the physics.

A network with thirty times the parameters and four times the training never learns the task. It is not beaten narrowly — it never leaves the baseline. What separates them is not size but whether the answer can be expressed without first learning that order does not matter.

Stated carefully

With enough data an ordinary network could memorise this map. The claim is about how much data you need and how well it generalises, not about what is possible in principle.

The second table

Flat, out to more than twice the training size. Nothing in the weights refers to how many objects there are — so you can train on the events you have and run on the events you get.

The flat second table is what matters most in practice.

Symmetry

What you get free, and what you must build

Attention gives you one symmetry exactly: relabelling the objects. Every other symmetry has to be put in, and there are three ways:

  • Use invariant features. Feed ΔR\Delta RΔR and pTp_TpT​ rather than raw angles, pair separations rather than coordinates. Simple, exact, and throws away whatever the invariants miss.
  • Build the group into the layers, as Lorentz- and E(3)E(3)E(3)-equivariant networks do. Exact and efficient with little data; considerably harder to write and to train.
  • Rotate the training data and let the model learn the symmetry. Easy, approximate, costs capacity — and often the right trade anyway.

Exact symmetry wins clearly when data is scarce. With large training sets the gap narrows, sometimes to nothing.

A worked instance

For jets, using (log⁡pT, Δη, Δϕ)(\log p_T,\ \Delta\eta,\ \Delta\phi)(logpT​, Δη, Δϕ) measured from the jet axis makes the input invariant under longitudinal boosts and azimuthal rotations without touching the architecture at all. Most of the benefit of a fully equivariant model, for a fraction of the work.

The symmetry you may not want

Ignoring order is a liability when order is physical — a causal sequence, a nested hierarchy. Then you have to put it back, and page 2 is how.

Rule of thumb

Match the symmetry of the model to the symmetry of the problem. A mismatch in either direction wastes capacity: too little must be learned, too much must be undone.

The "too much symmetry must be undone" case shows up whenever a set model is applied to genuinely ordered data.

The test to apply

Is your data naturally a set of things with attributes? If yes, a transformer is the default and the burden is on any alternative. If it is naturally a regular grid with local physics, a convolution is cheaper and usually better — and there is no shame in that answer.
