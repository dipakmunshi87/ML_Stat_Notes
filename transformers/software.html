Before you believe your own model.

Writing one attention layer yourself is about forty lines, as the engine behind these demonstrations shows; the libraries earn their place on speed and scale.

Libraries

What to install

The framework

PyTorch — nn.MultiheadAttention and nn.TransformerEncoderLayer cover the standard block, and scaled_dot_product_attention dispatches to a fused kernel automatically.

JAX + Flax — the better choice when you want to differentiate through a simulator as well, or need vmap over configurations.

Speed and scale

FlashAttention — exact attention, far less memory traffic. Use it; understand that it does not change the complexity.

HuggingFace transformers — pretrained models and a large collection of reference implementations to read.

torch.compile — usually a free speed-up on small models, which is exactly where physics work sits.

Physics-specific

weaver and particle_transformer — the reference jet-tagging training pipeline and the ParT implementation, with JetClass.

e3nn — E(3)E(3)E(3)-equivariant networks, for when the symmetry has to be exact.

PyTorch Geometric — graph attention on a known connectivity, which is often the right answer.

weaver is worth reading even if you do not use it: the data pipeline is a good model for how to handle variable-length physics input.

Libraries, continued

Around the edges, and one recommendation

Generative

diffusers for diffusion models with transformer backbones; flow_matching for the flow formulation; sbi for simulation-based inference with proper coverage diagnostics.

Error bars

An ensemble needs no library — train five models and look at the spread. MAPIE gives calibrated intervals with a guarantee. And GPyTorch is the baseline you should beat before reaching for a network at all.

Write one yourself, once

Attention is a matrix product, a row-wise softmax, and a second matrix product. Write it, check the gradient against finite differences, train it on a lookup. An afternoon, and every library stops being opaque. The code behind every demonstration here does exactly that, in about 500 lines of plain JavaScript with no dependencies.

If you take one recommendation

Start from nn.TransformerEncoderLayer with a class token, four heads, two layers, and your physical features as the token vector. Get that working end to end before changing anything. Most physics applications need a better representation, not a better architecture — which is the measured lesson of page 4.

The commonest failure of a first project is architectural elaboration before the baseline works.

Reading

Eight papers and where they fit

The mechanism

Vaswani et al., arXiv:1706.03762 (2017) — the original. Short, readable, and the 1/dk1/\sqrt{d_k}1/dk​​ argument is in a footnote.

Lee et al., Set Transformer (2019) — attention for sets, which is the physics case; induced set attention for the quadratic cost.

Dao et al., FlashAttention (2022) — how exact attention is actually computed on a GPU.

In physics

Qu, Li & Qian, Particle Transformer (2022) — jet tagging, JetClass, and pairwise physics features in the attention scores.

Allam & McEwen, arXiv:2105.06178 (2021) — transformers for photometric transient classification.

Bi et al., Nature 619, 533 (2023) — Pangu-Weather, the first learned model to beat operational NWP.

Generative

Wu, Wang & Zhang, Phys. Rev. Lett. 122, 080602 (2019) — variational autoregressive networks: the free-energy objective of page 6, and the cleanest bridge between the two fields.

Song et al., Score-Based Generative Modeling through SDEs (2021) — diffusion models as reverse-time SDEs.

If there is time for one paper beyond the original, make it the Set Transformer: it is the one that states the physics case explicitly.

Before you believe it

A checklist that catches real errors

  1. Gradient check the whole model. Finite differences against the analytic gradient on a few parameters: ten minutes, and it catches sign errors, off-tape nodes and broken masks — each of which fails silently.
  2. Overfit ten examples deliberately. If the loss will not go to zero on ten examples, the bug is in the model, not the data. Do this before any real training run.
  3. Check the mask. For a causal model, change the last input and confirm every earlier output is bit-identical. An off-by-one leaks the answer and looks like brilliance.
  4. Compare against a permutation. Shuffle the tokens; the prediction should be unchanged to floating-point precision. If it is not, something depends on order that should not.
  5. Beat a trivial baseline first. The mean, a linear fit, a nearest neighbour — and quote it. A model that does not beat the mean is a bug, not a result.
  6. Hold out properly, and report seeds. Whole runs, edge regions; several seeds with the spread.
The three that actually bite

A node built outside the tape — the gradient is silently zero, training freezes, no error is raised. This happened while building these pages: the gradient check passed and the loss did not move for 8,000 steps.
A leaky causal mask — performance that looks extraordinary.
A correlated train/test split — a test error that means nothing.

All three produce plausible output. None announces itself.

The companion sets

Physics-informed neural networks — the same autodiff machinery pointed at differential equations.
