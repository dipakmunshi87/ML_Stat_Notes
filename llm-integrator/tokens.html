Part 2 of 8 · the setup

From a curve
to a list of integers

A language model reads integers. Physics produces real numbers. The bridge is a lattice of allowed values, and choosing it is the only modelling decision in the whole experiment.

Everything in this set is decided by the lattice: it sets the ceiling on accuracy and, as page 5 shows, it also changes the dynamics.

The picture

Round each sample to the nearest line

Positions run from −1.3-1.3−1.3 to +1.3+1.3+1.3; 64 evenly spaced bins means a spacing of 0.041. Each sample is replaced by the index of its nearest bin.

The model then sees, say, 41 52 58 55 45 33 24 21 and must name the ninth number. Nothing in its input says these are positions.

The bin index is the "token"; the set of bins is the "vocabulary". Both words mean exactly what a physicist would call a quantised state and a state lattice.

The row that matters

"Autoregressive generation" and "time stepping" are the same loop, which is why the rest of this set can treat the model as an integrator and apply the standard machinery to it — stability, order, conservation.

The context window

The physics needs only two past values. The model is given eight. So it has more history than the law requires, and could in principle do better than the two-term rule — it does not.

A reader coming from either direction should be able to start here.

What the lattice costs

A ceiling, and a surprise

Rounding to the nearest bin throws away up to half a bin width, 0.0210.0210.021. Two consequences follow, and only the first is obvious.

It caps the accuracy. Even a model that knew the exact rule could not always name the right bin, because the true next value lands near a boundary often enough to matter. That sets a ceiling, and it is the number a measured accuracy should be compared against — not against 100%.

And it changes the dynamics. This is the surprise. Rounding is not a small random error added on top; it is a nonlinear map that pulls the state back onto the lattice at every step. That feedback fights any slow drift.

Measured on page 5: the model's own learned rule, iterated in exact arithmetic, loses 92% of its amplitude in a thousand steps. The same model, rounding to the lattice at every step as it actually does, loses 51%.

The tokenisation flatters the model. It is not the handicap you would assume.

Why this must be separated out

If you only measured the model, you could not tell how much of the error is the lattice and how much is the model. So the exact rule is also run through the same lattice, and the gap between that and the model is what the model got wrong. Every comparison in this set is done that way.

A familiar effect

Rounding at each step is a crude form of projection back onto a constraint surface — the same trick used to stop a constrained integrator drifting. Here it happens by accident.

The "rounding helps" result is the least intuitive thing in the set, and the reason the exact rule is also run in tokens.
